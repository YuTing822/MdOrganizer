# 我认为 Docker 网络模式的选择心得

我认为这块内容值得记一下。你们看，Docker 默认用的是 bridge 网络，容器之间要通过 IP 通信，我觉得挺麻烦的。我们来看一下自定义网络，你们就会发现它自带 DNS，容器名可以直接当域名用。

我认为 compose 里最好显式声明一个 network，你们看这样子服务名就自动能解析了。我们来看个例子：两个服务 web 和 db，只要在同一个 network 下，web 里就能直接 ping db。我认为这比 links 那种老写法干净多了。

你们看 host 模式，我认为它的好处是没有 NAT 损耗，性能最好，但是端口会直接占用宿主机，容易撞车。我们来看 none 模式，就是完全不给网络，我认为一般用来做纯计算任务。还有 macvlan，我认为它能让容器在物理网络里拿到独立 IP，你们看这在需要被外部设备直接访问的场合很有用。

我觉得要注意的一点是，我们来看 iptables 这块，我认为默认的规则会挡住跨主机的容器通信，你们看如果有多机需求，就应该上 overlay 网络，我认为 swarm 或者 k8s 都能用。我们来看最后一条：我认为排查网络问题时先 docker network inspect，你们看比瞎猜快多了。
